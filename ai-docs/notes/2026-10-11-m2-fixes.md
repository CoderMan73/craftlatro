# M2 Fixes: Path resolution and config persistence

## Problem
Two bugs identified during testing:
1. LocalHttpServer returns 403 "Forbidden" for static file requests due to path normalization mismatch
2. FidelityWarningScreen shows on every game restart because the acknowledgment is in-memory only

## Solution

### 1. LocalHttpServer path resolution fix
File: `src/client/java/com/craftlatro/client/server/LocalHttpServer.java`

- Normalized `serveDirectory` to absolute path in constructor (`serveDirectory.normalize().toAbsolutePath()`)
- Normalized `rootDir` to absolute path in `CoopCoepFileHandler` constructor
- Added `.toAbsolutePath()` to resolved file paths before `startsWith(rootDir)` check
- Same normalization applied to `htmlFile` (extension fallback path)
- Removed unused `java.io.File` import

Root cause: `Path.startsWith()` is lexical, not URI-based. If `rootDir` contained relative components or was not absolute, the normalized child path could fail the `startsWith` check even for valid files within the directory.

### 2. FidelityWarningScreen persistent acknowledgment
New file: `src/client/java/com/craftlatro/client/config/CraftlatroConfig.java`

- Singleton config that stores `warningAcknowledged` in `~/.craftlatro/config/craftlatro.properties`
- `getWarningAcknowledged()` / `setWarningAcknowledged(boolean)` methods
- Properties file loaded on init, saved on set

Modified `src/client/java/com/craftlatro/client/CraftlatroClient.java`:
- Replaced in-memory `warningShown` boolean with config check
- `onClientTick`: shows warning if `!config.getWarningAcknowledged()` and game not loaded
- `showFidelityWarning()`: sets `config.setWarningAcknowledged(true)` when screen is shown
- `openBrowserScreen`: uses `GameLauncher.getBaseUrl()` instead of hardcoded `http://localhost:18080/` (handles dynamic port)

Modified `src/client/java/com\craftlatro/client/ui/FidelityWarningScreen.java`:
- Removed CraftlatroConfig import (now handled by caller)
- "Select Balatro.exe" button just runs the callback

## Verification
- `./gradlew clean build` succeeds
- All classes compile against Rinku 3.0.4-26.2 and Fabric API 0.161.0+26.2

## Additional fixes applied
- **MIME type mapping** (`LocalHttpServer.java:138-164`): Explicit MIME types for .wasm, .js, .css, .html, .json, .lua files to ensure correct browser handling (especially `application/wasm` for love.wasm)
- **Content-Type header set**: The server now sets `Content-Type` header on successful responses (was missing entirely)
- **Port fallback** (`LocalHttpServer.java:43-60`): Server tries ports 18080-18089 if default is unavailable, storing the actual port
- **`getBaseUrl()` uses actual port**: Returns `http://localhost:<actual_port>/` instead of hardcoded 18080
- **Cleaned unused imports**: Removed `net.minecraft.network.chat.Component` and `net.minecraft.client.Minecraft` from LocalHttpServer, removed `java.io.File`
- **findZipStart optimization**: Replaced byte-by-byte scan with 64KB chunked reads for faster extraction
